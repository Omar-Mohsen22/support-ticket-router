# Adapter on ZeroGPU (bf16) vs the published adapter predictions (4-bit, T4)

Generated by `deploy/demo/measure_agreement.py`. Not part of `results/results.json`.

**The two runs are not the same setup:**
- **Published metrics** (`results/qlora-adapter-ckpt1500.predictions.jsonl`): the base model was loaded in **4-bit NF4 on a Tesla T4**, with the LoRA adapter attached (not merged), batch size 8. `inference.batch_size` in `train/config.yaml` is 8. The batch size is not recorded per run, but the predictions file shows identical per-row latency in 204 groups of 8 plus 1 of 1.
- **This measurement:** the demo Space loads the base model **unquantized in bfloat16 on ZeroGPU** (half an RTX Pro 6000 Blackwell), with the adapter merged (`merge_and_unload`), batch size **16**.
- Both use the same system prompt, chat template, left padding, greedy decoding (`do_sample=False`, `max_new_tokens=64`) and output validation, from `predictors/adapter_predictor.py`.

Batch size and left padding can themselves change a few outputs: the same ticket sees different padding, so numerics differ slightly. Any disagreement below is therefore **not attributable to precision alone**.

**Sample:** 1633 of 1633 test tickets, taken in a seeded shuffle order (`numpy.random.default_rng(29).permutation`), so a partial run is a random sample. Run status: **completed**.
